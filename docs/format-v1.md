# Bridge JSON v1 — контракт формата

Этот документ фиксирует минимальный контракт Stage 0. Он не обещает, что парсер уже реализован. Нормативный синтаксис — стандартный JSON (RFC 8259); расширение файла `.bridge.json`.

## Форма документа

```json
{
  "bridgeVersion": 1,
  "documentId": "demo.factory",
  "blocks": {
    "factory.settings": {
      "type": "simulation.settings",
      "schemaVersion": 1,
      "data": { "speed": 1.0, "gravity": 9.81 }
    }
  }
}
```

- `bridgeVersion` обязателен, целое число `1`. Иная или отсутствующая версия — диагностическая ошибка; молчаливых миграций нет.
- `documentId` обязателен и должен быть непустой строкой. Сравнение идентификаторов точное, с учётом регистра; пробелы и Unicode не нормализуются автоматически.
- `blocks` обязателен и является объектом `ID -> block`. Пустой объект допустим. ID блока — непустая строка, сравнение порядковое и чувствительное к регистру.
- `type` и `schemaVersion` обязательны у каждого блока; `type` — непустая строка, `schemaVersion` — целое положительное число. Выбрана обязательная версия схемы, чтобы версия данных блока была явной.
- `data` обязательно и может содержать любое JSON-значение, включая объект, массив, строку, число, boolean или `null`. Core не вводит предметную схему для этих данных.
- `refs` необязателен и содержит имена ссылок, значения которых имеют поля `document` и `block`. Ссылка — метаданные блока; поле `$ref` в `data` не имеет особого смысла.
- Повторяющиеся имена свойств JSON должны быть обнаружены и отклонены, в том числе повторяющиеся ID блоков.
- Неизвестные поля верхнего уровня и блока считаются расширениями. Целевой контракт — сохранять их при чтении и записи. Реализация должна подтвердить это тестами; если библиотека JSON этому препятствует, ограничение необходимо явно пересмотреть до реализации.

## Ссылки

`refs.<name>.document` — относительный путь к другому документу `.bridge.json`; пустая строка указывает на текущий документ. `refs.<name>.block` — точный ID целевого блока. Ссылки не подгружаются сами по себе и не встраивают целевые данные в сериализованный исходный документ.

На MVP по умолчанию запрещены абсолютные пути, URL/сетевые схемы, выход за разрешённый корень через `..`, циклическая или неограниченная загрузка. Внешние документы получает внедряемый `IBridgeDocumentResolver`; Core не требует файловую систему. Реализация должна ограничивать глубину и количество загружаемых документов, а поведение при символических ссылках задокументировать.

## Семантика JSON и запись

Round-trip `Parse -> Save -> Parse` сохраняет JSON-семантику, но не пробелы и не текстовое оформление чисел. Порядок элементов массивов сохраняется. Комментарии не входят в формат JSON. Детерминированная запись упорядочивает ID блоков, использует invariant culture и UTF-8, и не выдаёт NaN/Infinity как JSON-числа.

Парсер обязан отвергать trailing data после корневого значения. Для входа должны быть ограничения размера, глубины и количества блоков; конкретные настраиваемые значения по умолчанию фиксируются вместе с API загрузки на этапе 1 и не меняют сериализуемый формат.
