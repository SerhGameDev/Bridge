## Фактические API и разрывы с желаемым DX

Исходники проверены в `BridgeDocument.cs`, `BridgeMutations.cs`, `BridgeSerializer.cs`, `BridgeQuery.cs`, `BridgeDiagnostics.cs` и `BridgeValueAccess.cs`.

- Документ создаётся через `BridgeDocument.Create(string documentId)`, читается `Parse(string json, BridgeReadOptions? options = null, string? source = null)` и `Load(Stream stream, BridgeReadOptions? options = null, string? source = null)`. Поточный `Load` оставляет переданный поток открытым. Существуют `TryParse` и `TryLoad(Stream)` с `BridgeResult<T>`.
- Файлового фасада `BridgeFile` нет. Запись доступна через `BridgeDocument.Save(Stream, bool indented = false)`; `ToJson(bool indented = false)` возвращает JSON.
- Блоки доступны через `Blocks`, `TryGetBlock(string id, out BridgeBlock?)`, `GetBlock(string id)`, `AddBlock(...)` и `RemoveBlock(string id)`. У `BridgeBlock` есть `Get<T>(string field)`, `Set<T>(string field, T value)`, `Deserialize<T>()` и `Data`; краткого `ContainsBlock`/`HasField` и методов документа `Get/TryGet/Set` пока нет.
- Типовые ошибки представлены `BridgeException`, `BridgeDiagnostic` и `BridgeResult<T>`. Ошибки преобразования используют диагностический код `VALUE_TYPE`; отсутствующий блок — `BLOCK_NOT_FOUND`.
- `BridgeDocument.Serializers` — отдельный изменяемый `BridgeSerializer` для каждого документа. Конвертеры регистрируются явно через `Register<T>(Func<BridgeValue,T>, Func<T,BridgeValue>)`; нет reflection serializer, `dynamic` или JIT codegen.
- `document.Blocks` при каждом доступе формирует новый список, сортируя блоки ordinal по ID.
- Query builder immutable: `WhereType(string)`, `WhereId(string)`, `SelectFields(params string[])`, `Limit(int)`, `Execute()` и `TryExecute()`. QuerySpec принимает только `queryVersion: 1` и операции `type`, `id`, `fields`, `limit`; `WhereType` заменяет предыдущее значение Type. `WhereTypes` отсутствует.
- Удалённый `BridgeBlock` сохраняет ссылку на старое JSON-определение. Его `Set` после `RemoveBlock` может изменить detached JSON-объект, не меняя документ; добавление блока с тем же ID не оживляет ссылку, но API не предупреждает о потерянной записи.
- Верхний уровень формата, JSON-лексемы чисел, неизвестные поля, формат v1, LINQ и ограничения ссылок покрыты существующими acceptance-тестами; их поведение сохраняется.

## Совместимый план API

В v0.2 добавить удобный слой поверх существующих `BridgeDocument`, `BridgeBlock`, `BridgeSerializer`, `BridgeException` и `BridgeResult<T>`. Существующие stream API и низкоуровневые механизмы оставить.

Предлагаемые сигнатуры:

```csharp
public static class BridgeFile
{
    public static bool Exists(string path);
    public static BridgeDocument Load(string path, BridgeReadOptions? options = null,
        BridgeSerializer? serializers = null);
    public static BridgeResult<BridgeDocument> TryLoad(string path,
        BridgeReadOptions? options = null, BridgeSerializer? serializers = null);
    public static void Save(BridgeDocument document, string path, bool indented = true);
    public static void SaveAtomic(BridgeDocument document, string path, bool indented = true);
}

// Методы BridgeDocument
public bool ContainsBlock(string id);
public bool HasField(string blockId, string fieldName);
public bool TryGet<T>(string blockId, string fieldName, out T value);
public BridgeResult<T> TryRead<T>(string blockId, string fieldName);
public T Get<T>(string blockId, string fieldName);
public void Set<T>(string blockId, string fieldName, T value);

// Методы BridgeBlock и BridgeQuery
public bool HasField(string fieldName);
public BridgeQuery WhereTypes(params string[] types);
```

Правила аргументов: `null` даёт `ArgumentNullException`; пустой/whitespace путь, ID блока и имя поля даёт `ArgumentException`, а не обычный `false`. ID и имена полей сравниваются ordinal, с учётом регистра. `ContainsBlock` возвращает `false` для корректного, но отсутствующего ID. `HasField` проверяет только прямое поле в object-valued `data`, возвращает `false` для отсутствующего блока, отсутствующего поля и `data`, который не является объектом; существующее поле со значением JSON `null` даёт `true`. Точки и слеши в имени поля остаются буквальными символами.

`TryGet<T>` возвращает `false` только при отсутствии блока или поля и присваивает `default` в этом случае. Успешное чтение возвращает `true`; несовместимый тип/ошибка явного DTO-конвертера не маскируются как отсутствие и диагностируются как `BridgeException` (например, `VALUE_TYPE`). `TryRead<T>` — вариант без исключения для ожидаемых ошибок документа/конвертации: он возвращает `BridgeResult<T>` с кодом и контекстом. Некорректные аргументы API остаются programmer errors и бросают `ArgumentException`. `Get<T>` сообщает об отсутствующем блоке/поле и несовместимом типе через `BridgeException`; `Set<T>` меняет только существующий блок с object-valued `data` и не создаёт его автоматически.

`BridgeFile.Exists` лишь сообщает результат системной проверки существования и не валидирует содержимое или будущую доступность файла. `Load` открывает и закрывает собственный файловый поток; отсутствие, отказ IO/permissions и ошибка JSON/схемы должны иметь разные диагностические коды. Между `Exists` и `Load` возможна гонка, поэтому читаемость файла следует подтверждать результатом `TryLoad`.

`SaveAtomic` будет писать временный файл в целевой директории, сбрасывать пользовательские буферы, закрывать его перед заменой и очищать временный файл при отказе. Для существующего файла использовать замену, сохраняющую старый файл при ошибке; для нового — перемещение временного файла. Никакого fallback через удаление destination перед переносом. Атомарность зависит от ОС/файловой системы, а устойчивость к выключению питания не обещается без отдельной гарантии платформы. Фактические API `netstandard2.1`, Windows и Linux уточнить в подэтапе 1 и CI.

Для DTO предусмотреть явный повторно используемый набор converter-ов, но привязывать к документу независимую копию реестра. Существующий `document.Serializers` и `Register<T>` сохраняются. Регистрация до привязки; сериализаторы остаются явными, без reflection/dynamic/Expression.Compile/Reflection.Emit. Зафиксировать потокобезопасность в документации и покрыть двумя документами, Unity и AOT smoke.

Для нескольких типов `WhereTypes` использует OR внутри набора и AND с `WhereId`; последующий `WhereType`/`WhereTypes` заменяет type-фильтр immutable query. Дубликаты типов удаляются ordinal, сохраняется порядок результата документа, лимит применяется после фильтрации. Пустой список типов означает пустой результат. Один тип по-прежнему сериализуется в существующий QuerySpec v1 как `type`; multi-type получает QuerySpec v2 с массивом `types`. Парсер продолжает принимать v1 и v2, а старые JSON v1 остаются идентичными. Это необходимо, так как строгий v1 сейчас отвергает неизвестные поля.

Удалённый `BridgeBlock` будет инвалидирован по принадлежности и идентичности текущей записи; любые последующие операции чтения/записи дадут `BLOCK_REMOVED`. Повторное добавление того же ID создаст новый handle. Уже полученные immutable `BridgeValue` снимки останутся читаемыми.

`SaveAtomic` и file IO не будут использоваться резолверами refs: обычное чтение файла и ограниченное разрешение ссылок остаются разными сценариями. `HasField` останется top-level API; вложенные selection/path в v0.2 не добавлять. Если базовые подэтапы закончатся без риска для качества, вложенные запросы оформлять отдельным RFC для v0.3.
