# Решения по дизайну (Stage 0)

## Цель и границы

Bridge.Core — независимое ядро для хранения и чтения JSON-совместимых документов. Оно не зависит от UnityEngine и не знает о симуляции, AI, MCP, PLC, командах или runtime. Данные из файлов не исполняются. Авторизация и политики доступа относятся к будущему слою, не к Core.

## JSON и модель

Используется стандартный JSON и расширение `.bridge.json`, без собственной грамматики. Контракт версии документа — `bridgeVersion: 1`; блок содержит явный `schemaVersion`. Неизвестная версия документа приводит к понятной диагностике. Поле `data` остаётся произвольным JSON значением, а `refs` — отдельными метаданными.

На этапе реализации будет выбран зрелый JSON пакет после проверки доступности для .NET Standard 2.1 и Unity. Newtonsoft.Json рассматривается как кандидат, но версия пакета и фактическая совместимость не заявляются до проверки. Детали DOM следует скрыть за API Bridge.Core, где это практически возможно.

## DTO и AOT

DTO сериализуются через явно зарегистрированные типизированные сериализаторы/конвертеры для предсказуемой работы с AOT. Любой reflection-based удобный путь будет документирован как отдельный вариант и подтверждён реальными проверками; dynamic, Reflection.Emit и JIT-компиляция не используются.

## Коллекции и запросы

`Blocks` проектируется как типизированная `IEnumerable<BridgeBlock>`-коллекция для стандартного локального LINQ. Дополнительно будет ограниченная модель `BridgeQuerySpec` с фильтрами по типу/ID, выбором верхнеуровневых полей `data` и limit. Запрос не принимает произвольные лямбды из файла и возвращает неизменяемую проекцию/snapshot.

## Ссылки

Ссылки — именованные метаданные блока. Core не загружает файлы сам без вызова внедряемого резолвера. Для безопасного локального резолвера необходим явно заданный корень, нормализация и проверки пути, лимиты и защита от циклов. In-memory resolver подходит Unity и тестам без доступа к диску. Политика кеша ограничивается одной операцией разрешения, если реализация не докажет необходимость и безопасность другого срока жизни.

## Ошибки и версии

Ожидаемые ошибки чтения, схемы, поиска и ссылок представлены диагностикой/Result-подобной формой; неверное использование API может приводить к отдельным исключениям программиста. Диагностика включает код, уровень, сообщение и известные координаты JSON без придуманных line/column. Детальная форма API будет закреплена на этапах реализации.

## Репозиторий и единый источник

Локальный путь проекта: `C:\GitHub\Bridge`. Ветка разработки начинается с `main`. Для .NET проект в `src/Bridge.Core` будет компилировать единственный набор `.cs`-файлов из `Packages/com.serhgamedev.bridge.core/Runtime` через linked Compile items. Так UPM и .NET используют один исходный код, без синхронизации копий. На этапе 5 схема будет подтверждена импортом UPM-пакета в Unity.

Лицензия — MIT, владелец `SershDev`, 2026. Целевая платформа ядра — `netstandard2.1`. Пакет Newtonsoft не включается копией DLL в репозиторий. NuGet публикация и GitHub release запрещены без отдельной команды пользователя.

## Неизвестное / отложенное

- Версия Newtonsoft и конкретный способ связи с UPM устанавливаются после проверки инструментов и Unity.
- Численные значения лимитов чтения задаются вместе с API на этапе 1.
- Stage 0 фиксирует контракт и scaffold, а не реализацию, успешные тесты или фактическую совместимость с IL2CPP.
